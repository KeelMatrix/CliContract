# Privacy

KeelMatrix CliContract processes command-line schema files locally. It never fetches a network resource and makes no network access while parsing or comparing. Remote schema references that would require resolution, including `$ref`, `$dynamicRef`, `$recursiveRef`, includes, and remote document references, are rejected fail-closed with `OPENCLI_REMOTE_REFERENCE` and CLI exit code `3`. Schema-valid scalar URL values in informational metadata, such as `info.contact.url`, `info.license.url`, and `info.install.url`, are accepted and preserved verbatim in the canonical manifest; they are data only and are never fetched.

After a successful comparison with a nonempty baseline, version 0.1 requests one best-effort activation through the published `KeelMatrix.Telemetry` package. The request passes no schema-derived values. The shared contract may emit an activation event, telemetry schema version, anonymous project and installation hashes, a generic tool label, tool version, runtime/platform, CI indicator, and timestamp; it does not receive command names, options, aliases, descriptions, defaults, accepted values, schema contents, baseline contents, repository names, paths, or diagnostics. The optional activation request is the only network behavior.

The tool reads only paths supplied to its commands and writes a snapshot only when `snapshot --output` succeeds. Diagnostics use stable codes and logical paths; they do not echo complete schemas, descriptions, defaults, credentials, repository names, or filesystem paths. Duplicate normalized argument or option names, and command keys that normalize to the same logical path, fail closed with `OPENCLI_DUPLICATE_PARAMETER` or `OPENCLI_DUPLICATE_COMMAND_PATH` and exit code `3`.

The compatibility decision models accepted invocation names, including aliases at every command segment, all supported OpenCLI type and choice domains, positional arity, and argument passthrough. Choices and defaults are checked against their declared types before they can be snapshotted; exact numeric representation and integer detection are shared with compatibility comparison so accepted manifests remain reflexive. Global and command exit-code metadata is retained and reported as a warning when changed. Opaque `x-*` extension data is accepted but outside the compatibility decision. Missing source or canonical-baseline paths return exit `2`; present read/encoding/size/parse/validation failures return exit `3`; suppression/configuration and output-write failures return exit `2`; unexpected failures return exit `4`. See [`docs/ERROR-TAXONOMY.md`](docs/ERROR-TAXONOMY.md).

`--no-telemetry`, `KEELMATRIX_NO_TELEMETRY=1`, `KEELMATRIX_DEVELOPMENT=true`, and `CI=true` disable the activation request; development and CI are always telemetry-suppressed. There is no periodic heartbeat. Any telemetry construction or delivery failure is swallowed so it cannot affect tool behavior. See [`KeelMatrix.Telemetry`](https://github.com/KeelMatrix/Telemetry) for the canonical shared field and retention policy.
